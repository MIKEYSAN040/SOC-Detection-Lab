# Attack Analysis

## Overview

The dataset demonstrates Active Directory discovery activity commonly associated with BloodHound.

BloodHound collects information from Active Directory by communicating with Windows Remote Procedure Call (RPC) services through the administrative `IPC$` share. During collection, it queries multiple named endpoints to gather information about users, groups, computers, sessions, and trust relationships. :contentReference[oaicite:1]{index=1}

---

## Attack Timeline

### Stage 1 — Initial RPC Communication

The user account:

user01

connected from:

10.0.2.17

using the administrative share:

IPC$

This establishes the communication channel used for RPC-based discovery.

---

### Stage 2 — Account Enumeration

Multiple Event ID 5145 events recorded access to:

samr

The Security Account Manager Remote (SAMR) interface provides information about users, groups, and local administrator memberships.

---

### Stage 3 — Security Policy Enumeration

The attacker accessed:

lsarpc

This interface provides access to Local Security Authority (LSA) information, including security identifiers (SIDs), policies, and trust-related information.

---

### Stage 4 — Domain Enumeration

Additional RPC requests targeted:

NETLOGON

and

srvsvc

These interfaces help identify domain controllers, servers, network shares, and authenticated sessions.

---

## Attack Outcome

The repeated RPC requests observed over the `IPC$` administrative share indicate automated Active Directory reconnaissance consistent with BloodHound enumeration. This information is typically collected to identify privilege escalation opportunities and plan later stages of an intrusion.
